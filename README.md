# 茶叶拼配审评台

审评员对一个拼配批次打香气、滋味、汤色。服务端按 0.3 / 0.5 / 0.2 加权，7 分及以上通过。提交后只替换表格里新的一行，不整页跳转。

拼配配方走「草案 → 生效版本」流程：

- 草案阶段可反复改母叶清单；点「生效」后生成只读、带全局版本号的快照（首次生效即版本一）。
- 已生效版本不可改、不可删（数据库触发器拦截 UPDATE/DELETE）；要调整只能新建草案再生效出版本号。
- 交评必须从下拉里挑一个**已生效版本号**，否则服务端拒交（400）。
- 审评员（writer）可建草案、点生效、交评；观察员（reader）只能翻版本列表、看生效正文，不能建草案、不能生效、不能交评。
- 顶栏「配方版本」进入配方版本专页。

这是制茶审评，不是菜谱，也不是饮食记录。

## 验收

1. taster 登录后看到春茶-A 通过、夏茶-C 不通过。
2. 再提交一组高分，新行出现在表头，页面不整页刷新。
3. observer 登录后没有提交表单。
4. 顶栏「配方版本」进专页：taster 建草案、勾两味母叶、点生效，得到只读「版本 1」。
5. 回交评页交一批「春芽」并选择版本 1，提交成功，表格新行带「版本 1」；不选版本或选不存在版本均被拒交（400）。
6. 再建草案改母叶并生效得到「版本 2」，版本 1 正文不变；版本 1 已无法再编辑（404）。
7. observer 在配方专页能翻版本列表、打开只读正文，但看不到建草案入口，强发建草案/生效/交评请求一律 403。
